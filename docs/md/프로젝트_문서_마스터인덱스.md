## 2. 버전 관리 규칙

- **작업 중에는 문서를 버전업하지 않는다.** 스펙 변경은 §5 변경 노트에 누적한다.
- 마일스톤 하나가 끝나면 Major(+1.0) / Minor(+0.1)를 판단해 **한 번에** 버전업한다.
- 버전업 시 전체 명세서 · 요약본 · 변경사항 3종을 동시에 만들고, 데이터·API·기능·UI 정합성을 일괄 검증한다.

### U-신규 결정 — 파생값을 장부에 어디까지 올리나 (2026-08-02, M7)

N69 안건이다. 세 갈래를 놓고 사용자가 **"최대와 중간 중 가장 좋은 효율"** 을 골랐다.

### U-신규 결정 — 본문 연결률을 서버가 잴 것인가 (2026-08-02, M7)

대가는 **같은 규칙이 두 곳에 생긴다**는 것이다. 어긋나면 화면이 보여 주는
연결률과 점수가 달라지고, 그러면 둘 중 하나는 거짓말이 된다. 검사 두 겹으로 막는다.

```
regress_ui.js 6절   서버 없이 · 규칙의 모든 갈래를 건드리는 15줄을 양쪽에 넣어 줄 단위 대조
run_harness.js      실제 리포트 전문으로 서버 값 = 브라우저 값 (네 작업 전부)
```

파이썬 쪽을 못 돌리면 **초록불로 세지 않고 실패로 센다** — 대조를 건너뛴 채
통과하면 어긋남을 놓친 것과 같기 때문이다.

`toFixed()` 는 자바스크립트가 '올림', 파이썬이 '짝수로' 라 그대로 옮기면 어긋난다.
`Decimal(float)` 로 double 의 정확한 이진값을 잡아 `ROUND_HALF_UP` 으로 자른다.
`Math.round` 는 `math.floor(x + 0.5)` 다.

**한 번 실제로 어긋났다.** IND-TP 후보 시총 비중을 `round(x*100, 2)` 로 한 번 더
반올림해 올렸더니 리포트 표기 `99.4%` 와 장부 값 `99.35`(→ 99.3)가 갈려 안 이어졌다.
**파생값은 원값 그대로 싣고 반올림은 표기하는 쪽에서만 한다.**

### U-신규 결정 — 근거 드릴다운의 범위 (2026-08-02, M6)

명세 §7.2 는 "**모든 수치가 클릭 가능한 근거 링크다**" 를 참고 이미지와의 차별점으로 못박았다.
그래서 만들기 전에 **본문 수치가 실제로 장부와 얼마나 이어지는지**를 네 작업 전부 재 봤다.

| 작업 | 본문 수치 토큰 | 단일 매칭 | 값이 같은 D- 가 둘 이상 |
|---|---:|---:|---:|

| IND-R | 40 | **3 (8%)** | 4 |
| CORP-TP | 30 | **3 (10%)** | 0 |
| IND-TP | 75 | **0 (0%)** | 36 |

**낮은 이유는 버그가 아니다.** D- 45건은 원시 계정(`revenue`·`operating_income`·`equity` …)인데
본문에 나오는 것은 그걸 가공한 값이다.

```
1위 SK하이닉스 · adjusted 4.6 · coverage 100%       ← 점수 · D- 없음 (CALC- 는 있으나 inputs 가 비어 있다)
```

**세 갈래를 놓고 사용자가 골랐다.**

| | 무엇 | 판단 |
|---|---|---|
| A | UI 만 — 장부 뷰 + 장 단위 근거 + 본문은 확실한 것만 링크하고 연결률을 밝힌다 | ✅ **채택** |

| C | 본문 링크를 아예 걸지 않고 장부 뷰만 | — |

B 를 지금 하지 않은 이유는 **E-/D-/CALC- 번호가 전부 밀리기 때문**이다. M4·M5 실측 표
(E/D/C/Gap · 최대 팩 크기)와 회귀 기준선을 다시 재야 하는데, 그건 UI 마일스톤에 섞을 일이 아니다.

**A 가 지키는 선** — 값이 D- 와 정확히 맞고 **같은 줄에 그 지표 이름이 있을 때만** 링크한다.
값이 같은 D- 가 둘이면 걸지 않는다 (IND-TP 에서 36건이 그렇다 — 구성 종목 93곳의 ROE 가
겹친다). 그리고 화면이 "본문 수치 73개 중 10개가 근거로 이어진다. 나머지는 파생값이라
장부에 D- 번호가 없다" 를 그대로 적는다. **못 이었다는 사실을 숨기는 것이 링크를 못 거는 것보다 나쁘다.**

원자료는 **장부 탭**에 전부 있다 (D- 를 누르면 D- → CALC- → E- 사슬이 열린다).
IND-* 는 335행이 그대로 열린다.

### U5 결정 — HuggingFace 를 어디에 쓰나 (2026-08-02, M5)

사용자가 **뉴스 감성과 산업 분류 둘 다** 하겠다고 했고, HF Access Token 을 `.key` 에 넣어 줬다.
남은 문제는 "어떻게" 였다 — **`transformers`+`torch` 는 2GB 라 배포 번들(한도 500MB)에 못 들어간다.**
그래서 **원격 추론 API** 로 쓴다. 새 파이썬 의존성은 0개다.

| 용도 | 모델 | 실측 |
|---|---|---|
| 공시 제목 감성 | `snunlp/KR-FinBert-SC` | 불성실공시 → negative **0.9997** · 현금배당 → positive **0.9999** · IR개최 → neutral 0.9999 |
| 밸류체인 위치 분류 | `joeddav/xlm-roberta-large-xnli` | "반도체 메모리 D램 낸드플래시 파운드리" → **반도체 0.986** |

**모델을 가려야 했다.** 같은 문장으로 `facebook/bart-large-mnli` 를 재 보니
`bank 0.30 · automobile 0.26 · semiconductor 0.25` 로 **오답**이었다. 영어 전용 NLI 모델은
한국어를 사실상 못 읽는다. 다국어 모델로 바꾸니 0.986 이 나왔다.

**응답 모양에 함정이 있었다.** `top_k` 를 안 주면 텍스트 3개를 보냈을 때
`[[{negative},{neutral},{positive}]]` 가 오는데, 이게 "3개 입력의 top-1" 인지
"1개 입력의 3라벨 분포" 인지 모양만으로는 구분되지 않는다 (라벨이 3개라 겹친다).
→ **`parameters.top_k = 1` 을 반드시 붙인다.**

| 지연 (실측) | 콜드 | 웜 |
|---|---:|---:|
| 감성 배치 30건 | 3.65초 | 0.66초 |
| 제로샷 분류 1건 | — | 1.14초 |

지킨 경계 세 가지

- **없으면 못 도는 자리에 쓰지 않았다.** 실패하면 `{"available": False, "reason": ...}` 를
  돌려주고 리서치는 규칙 기반으로 계속 간다 (불변원칙 §2-2).
- **낮은 점수를 사실처럼 싣지 않는다.** 제로샷 1순위 점수가 0.5 미만이면 판정을 유보한다.
  실측 — '반도체 제조업' 이 `완제품·조립 0.34` 로 나왔다. 라벨이 7개라 무작위면 0.14 인데
  0.34 는 그보다 높을 뿐 "이거다" 라고 말할 값이 아니다.
- **'뉴스 감성' 이라고 쓰지 않는다.** 우리에겐 뉴스 원문 소스가 없다. 넣은 것은 **DART 공시 제목**
  (삼성전자 12개월 79건)이고, 본문이 없어 문맥이 빠진다는 한계를 해석카드에 그대로 싣는다.

### U8 결정 — 금융감독원 API 용도 (2026-08-02, M5)

사용자가 "밸류에이션을 할 때 **가장 신뢰성 있는 곳의 값**을 쓰고 싶다" 고 했다.

**② 금융업 재무비율 예외 판정**

```
고친 뒤     신한지주 부채비율 1,201.94%  →  ⚪ 금융업이라 제조업 기준(100%/150%)으로 읽지 않는다
```
