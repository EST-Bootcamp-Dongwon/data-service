## 1. 배경

현재 `api-test`는 공공 OpenAPI를 호출해 차트로 그리는 **실습 저장소**다. 계층 분리(`clients → repositories → services → routers`)는 이미 깔끔하고, 화면 8개가 각각 자기 API만 호출한다. 데이터를 보여주는 것까지는 잘 되어 있다.

문제는 **거기서 끝난다**는 것이다.

- 차트는 그려지지만 "그래서 무슨 뜻인가"가 없다.
- 화면 8개가 서로 남남이다. 상단 가로 nav 하나로 나열되어 있어 위계가 보이지 않는다.
- 강의에서 배운 것(04 통계 · 05 시계열 · 06 크롤링 · 08 투자분석)이 코드에 반영되어 있지 않다.
- 별도로 설계한 리서치 방법론([GIC v15.0](https://github.com/dev-dongwon05253/Research-Prompt-Engineering))이 문서로만 존재하고 실행되지 않는다.

이 넷은 사실 같은 문제다. **수집한 데이터를 검증된 근거로 바꾸고, 근거를 해석으로, 해석을 예측으로 잇는 절차가 없다.**

## 2. 이 리팩토링이 하려는 것

GIC v15.0 하네스 공통계약을 읽어 보면, 그것이 사실상 **상태 기계 명세서**라는 점이 드러난다.

- 상태 `H00`~`H11` 12단계 (Initialize → Scope → Evidence → Normalize → Analyze → Visualize → Interpret → Red Team → Human Review → Assemble → Evaluate → Complete)
- Context Pack `C0`~`C6` 블록별 읽기·쓰기 권한
- Evidence ID · Data ID · Calculation ID 추적 계약
- Gap/Conflict 코드 15종
- 100점 평가 루브릭 + 회귀검사 8항목
- 단계마다 사용자 질문 2~4개와 Feedback Log

이건 LLM에게 부탁하는 글이기 이전에 **구현 가능한 명세**다. 그래서 이 리팩토링의 핵심은 하나로 요약된다.

> **GIC v15.0 명세를 서버 코드로 실행하고, 그 결과를 사이드바 기반 대시보드로 보여준다.**

수치·판단·근거는 전부 서버가 결정론적으로 계산한다. LLM은 쓰지 않는다. 같은 종목·같은 기준일이면 언제 실행해도 같은 결과가 나온다.

## 4. 비목표 (Non-goals)

명시적으로 **하지 않는 것**이다. 범위가 새는 걸 막기 위해 적어 둔다.

- **투자자문·매매 신호 아님.** GIC 공통계약 §17을 그대로 따른다 — 교육·리서치 자료이며 최종 판단은 사람이 한다. 모든 리포트에 고지를 넣는다.
- **실시간 트레이딩 아님.** 데이터는 15분 이상 지연된다.
- **LLM API 연동 아님.** 리포트 문장은 해석카드 5문장 규칙을 따르는 템플릿으로 조립한다.
- **GIC 저장소 수정 아님.** 원본은 읽기만 하고, 이 저장소로 가져와 커스터마이징한다. 예외적으로 완성 후 GIC 저장소 `README.md`에 **배포 주소 한 줄 추가**만 PR로 제안한다.
- **머신러닝 모델 학습 아님.** (보충이 필요한 지점은 §8 리스크 R4 참고)

## 5. 핵심 설계 결정

각 결정의 근거를 남긴다. 나중에 뒤집을 때 무엇이 달라지는지 알기 위함이다.

### D1. GIC 하네스를 코드로 실행한다 (LLM 미연동)

GIC 문서를 "구현 명세서"로 삼아 `app/services/research/` 아래에 이식한다. 판단 규칙(피어 선정, 점수 가중치, Proceed/Watch/Drop 임계값)은 전부 코드의 상수와 함수로 표현한다.

- **장점**: 비용 0 · 100% 재현 · 환각 구조적 차단 · 근거 추적 완벽
- **대가**: 문장이 템플릿에 갇힌다 → 해석카드 5문장(관찰·의미·인과·반대해석·한계·다음검증) 구조를 살려 조립 규칙을 촘촘히 만들어 완화한다
- **부가**: 같은 Context Pack을 GIC 양식 MD로 내보내는 버튼을 둔다. 외부 LLM에 붙여넣고 싶으면 그때 쓴다 (G7)

### D2. Context Pack은 클라이언트가 보관한다 (Stateless 서버)

Vercel 서버리스는 요청 간 메모리를 공유하지 않는다. 그래서 서버를 **순수 함수**로 만든다.

```
(Context Pack, state_id, 사용자 답변) → (갱신된 Context Pack, stage_result)
```

브라우저가 Context Pack을 들고 있다가 다음 단계 요청에 실어 보낸다.

- GIC 공통계약 §4가 각 상태의 `대표 Context 읽기`를 이미 정의해 두었으므로, **필요한 블록만** 보내면 된다
- 60초 제한을 구조적으로 회피한다 (한 요청 = 한 단계 = 5~10초)
- 재현성·감사추적이 저절로 따라온다 — C6 변경 이력이 클라이언트에 그대로 쌓인다
- 외부 DB 불필요

### D3. 시계열 엔진은 numpy로 직접 구현한다

`scipy`(~90MB) · `statsmodels`는 Vercel 번들 한도상 넣을 수 없다. 대신 05강의 내용을 직접 짠다.

| 기능 | 구현 방법 |
|---|---|
| 고전 분해 (추세·계절·잔차) | 중심이동평균 |
| 정상성 검정 (ADF) | MacKinnon 임계값 테이블 하드코딩 |
| ACF · PACF | numpy 상관 + Bartlett/Quenouille 신뢰밴드 |
| AR(p) | OLS (`numpy.linalg.lstsq`) |
| ARIMA(p,d,q) | Hannan-Rissanen 2단계 OLS |
| 예측 신뢰구간 | ψ-weight 전개 + 잔차분산 |

배포 번들에서 `matplotlib`·`fontTools`·`PIL`을 제외하면 **약 82MB**가 비므로 여유도 생긴다 (해당 라이브러리는 `scripts/`만 쓰고 서버는 import 하지 않는다).

부수 효과가 더 크다 — 라이브러리를 부르는 대신 **강의 내용을 직접 구현**하게 되므로 학습 목적에 정확히 맞는다.

### D4. 시계열은 yfinance 실시간, 스크리닝은 스냅샷

- **개별 종목 시계열**: 요청 시 yfinance 호출 (미국 0.25초 / 국내 7.2초 실측)
- **전체 시장 스크리닝**: 사전 계산한 압축 스냅샷을 저장소에 커밋 (수 MB)
- **캐시**: Vercel `/tmp`(512MB 쓰기 가능)를 best-effort 캐시로 쓴다. 인스턴스가 재사용되면 히트, 아니면 재조회. **정합성은 stateless 설계가 보장하고 `/tmp`는 속도만 담당**한다
- `data/krx_cache.db`(100MB)는 로컬 전용으로 남기고 배포에는 올리지 않는다

### D5. 순수 HTML/CSS/JS를 유지한다

빌드 툴 없이 FastAPI가 정적 파일을 서빙하는 현재 구조를 지킨다. 사이드바는 `app.js`가 렌더링하므로 **한 곳만 고치면 전 화면에 반영**된다 (지금의 `renderNav`와 같은 패턴).

### D6. 예측은 3단으로 쌓아 올린다

| 단계 | 산출물 | 정직성 장치 |
|---|---|---|
| 1. 통계 예측 | ARIMA 점예측 + 95% 신뢰구간 | 구간 폭을 그대로 보여준다 |
| 2. 방향성 확률 | N영업일 상승확률 (%) | walk-forward 백테스트 적중률 병기 |
| 3. 시나리오 | Bear/Base/Bull + 트리거·반증 조건 | 각 시나리오의 반전 경계를 명시 |

**확률보행(Random Walk) 벤치마크를 항상 함께 계산한다.** 모델이 확률보행보다 못하면 리포트에 그 사실을 그대로 적는다. GIC 불변원칙 §2-1(확인되지 않은 것을 만들지 않는다)의 시계열 버전이다.

## 6. 사용 시나리오

**시나리오 A — 기업 리서치 (CORP-R)**

1. 사이드바 `리서치 › 기업 리서치` → 자동완성으로 `삼성전자` 선택
2. `리서치 실행` 버튼 → 진행률 모달이 뜬다
3. `H01 Scope`에서 모달이 멈추고 묻는다: *"기준일을 최근 거래일로 할까요, 최근 분기말로 할까요?"* · *"피어 그룹을 시총 기준으로 잡을까요, 업종 기준으로 잡을까요?"*
4. 답하면 `H02 Evidence`(DART 공시·KRX 시세·FRED 거시 수집) → `H03 Normalize`(회계기간·단위·통화 정규화) → ... 진행률이 오른다
5. `H07 Red Team`에서 반대 근거가 자동 생성된다: *"매출 성장은 확인되나 환율 기여를 분리하기 전 경쟁력 강화로 단정할 수 없다"*
6. `H11 Complete` → 15장 리포트 + 100점 자기평가 + Gap Log
7. 리포트의 `영업이익률 12.4%`를 클릭 → `D-CORP-R-0043` 카드가 열려 DART 원문 위치·기준일·계산식 표시
8. `MD로 내보내기` 버튼 → GIC 양식 마크다운 다운로드

**시나리오 B — 대시보드**

사이드바 `대시보드`를 열면 카드 그리드가 뜬다. 지수·환율·금리·시장온도 카드 각각에 값 + 스파크라인 + 상태등급(과열/중립/침체)이 있고, 아래에 최근 실행한 리포트 목록이 붙는다.

## 7. 범위와 마일스톤

토큰·컨텍스트 부담을 줄이기 위해 **마일스톤 단위로 세션을 끊는다.** 각 마일스톤 종료 시 커밋 → push → 다음 세션 인계 프롬프트 제공.

| M | 이름 | 산출물 | 선행 |
|---|---|---|---|
| **M0** | 설계 | 기획서 · 명세서 · 마스터인덱스 | — |
| **M1** | UI 셸 | 사이드바 셸 · 디자인 토큰 · 대시보드 카드 그리드 · 기존 8화면 이식 | M0 |
| **M2** | 데이터 계층 | DART·ECOS 클라이언트 · corp_code 매핑 · 스냅샷 빌더 · 전처리 파이프라인 | M0 |
| **M3** | 시계열 엔진 | `services/timeseries/` 전체 + 백테스트 검증 | M2 |
| **M4** | 하네스 코어 | `services/research/` 계약·장부·H00~H11 + **CORP-R** 완성 | M2, M3 |
| **M5** | 나머지 3작업 | IND-R · CORP-TP · IND-TP | M4 |
| **M6** | 리포트 UI | 진행률 모달 · 근거 드릴다운 · MD 내보내기 | M1, M4 |
| **M7** | 배포·마감 | 번들 최적화 · Vercel 검증 · README · GIC 저장소 PR(배포주소 1줄) | 전부 |

M1과 M2는 서로 독립이라 순서를 바꿔도 된다.

- [ ] 사이드바에서 모든 화면에 도달 가능하고, 기존 8화면 기능에 회귀가 없다
- [ ] MD 내보내기가 GIC 양식을 지킨다
- [ ] 모든 리포트에 교육·리서치 목적 고지가 붙는다
