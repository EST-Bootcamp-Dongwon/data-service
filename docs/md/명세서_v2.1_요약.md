## 0. 이 문서를 읽는 사람에게

**다음 세션의 작업자**를 위한 문서다. 전체 명세(2,543행)와 변경노트 82건을 읽지 않고도

세 가지 원칙이 이 프로젝트 전체를 지배한다. 코드를 고치기 전에 이것부터 읽어라.

## 1. 한 장짜리 시스템 지도

### 1.1 무엇을 만든 것인가

> **GIC v15.0 리서치 하네스 명세를 서버 코드로 실행하고, 그 결과를 사이드바 대시보드로 보여준다.**

LLM 은 쓰지 않는다. 수치·판단·근거는 전부 서버가 결정론적으로 계산한다.
같은 종목·같은 기준일이면 언제 실행해도 같은 결과가 나온다.
(예외 — HuggingFace 추론 API 는 **없어도 도는 자리**에만 쓴다. §5.6 참고)

### 1.2 계층 (아래는 위를 import 하지 않는다)

                ────
                78개  app/ 아래 .py 전수 (2026-08-02 · `find app -name "*.py" | wc -l`)
                      아래 계층 수는 각 폴더의 __init__.py 를 포함한 값이다 (총 11개)

**사장 모듈이 하나 있다.** `app/services/research/knowledge/technical.py`(531행)는
`app/` · `main.py` · `static/` · `tests/` 어디에서도 import 되지 않는다.
실제로 import 되는 knowledge 모듈은 `financials` · `macro` · `valuation` · `portfolio` · `glossary` 다
(`stages.py:36` · `workstreams/*.py` · `research_router.py:30`).
**기술적 분석은 리포트에 반영되지 않는다** — 파일이 있다는 것과 쓰인다는 것은 다르다.
나머지 77개는 전수 확인 결과 전부 참조된다.

CORP-R 1,770.0KB · CORP-TP 2,320.5KB · IND-R 2,526.6KB · IND-TP 2,696.3KB —

```python

### 5.1 `E-` 근거 레코드 (C1)

`id` `claim` `direction`(support/contradict/context) `source` `url` `published` `as_of`
`collected` `location` `grade` `grade_reason` `directness` `recency` `confidence` `reason`

**등급은 출처에서 자동 판정한다** (`ledger.SOURCE_GRADES`). 사람이 손으로 고르면
같은 출처가 실행마다 다른 등급을 받아 커버리지 평가가 의미를 잃는다.

| 등급 | 뜻 | 예 |
|---|---|---|
| `1차공식` | 정부·규제기관·거래소가 **직접 생산** | DART 공시목록·기업개황 · KRX · ECOS · FRED · KOSIS |
| `회사원문` | 회사가 작성해 제출한 원문 | DART 재무제표 · 사업보고서 |
| `2차전문` | 전문 사업자가 모아 재배포 | yfinance |
| `기타` | 표에 없는 출처 — **사람이 확인해야 한다** | |

H10 은 `1차공식`·`회사원문` 둘만 `PRIMARY_GRADES`(원생산자)로 센다.

### 5.2 `D-` 데이터 레코드 (C2)

`id` `metric` `value` `unit` `currency` `period` `basis` `actual_or_estimate`
**`evidence_id`** **`calc_id`** `transform` `rounding`

> `evidence_id` 와 `calc_id` 는 **둘 중 하나**가 채워진다.
> 원자료는 E- 에서 오고(`evidence_id`), 파생값은 계산에서 온다(`calc_id`).
> 둘 다 비면 그 값은 되짚을 수 없다는 뜻이고, 커버리지가 그것을 그대로 센다.

### 6.2 왜 파생 D- 에 `evidence_id` 를 안 붙이나

입력의 E- 를 물려주면 **"밸류에이션 밴드 하단 158,549원(`D-CORP-R-0121`)의 출처가 DART 재무제표"** 가 되어
우리가 만든 값을 남이 발표한 값처럼 보이게 한다 (불변원칙 §2-1).
**사슬은 끊기지 않는다** — `파생 D- → CALC- → 입력 D- → E-` 로 이어진다.

## 8. 절대 어기면 안 되는 것

### 8.1 계층 규칙

```
routers/ → services/ → repositories/ → clients/ → core/
```

- **아래는 위를 import 하지 않는다.** `core/parallel.py` 는 아무것도 import 하지 않는다.
- 저장소는 원본이 비면 **축약본 → 라이브** 순으로 갈라진다. `krx_store.source()` 가
  `cache` | `bundle` | `live` 중 무엇인지 밝힌다.
- ⚠️ **현재 이 규칙이 한 곳에서 깨져 있다** — `research_router.py:142·144·146` 이
  `industry_store._cache` · `snapshot_store._snapshot` · `glossary._cache` 라는
  **사설 속성을 직접 읽는다**(warmup). 저장소 내부 변수명이 바뀌면 조용히 깨진다.

### 8.2 계약

- `stage_result` **21필드를 더하지도 빼지도 않는다.** `run_harness.js` 가 전수 검사한다.
- Context Pack `C0`~`C6`·`logs` 의 **필드명을 바꾸지 않는다.** 확장은 `CX_workstream` 에만.
- 값을 고칠 때 `contracts.set_field` / `record_change` 를 **반드시** 거친다 (§6 흔적 없는 덮어쓰기 금지).
- Gap/Conflict 코드는 `contracts.CODES` 15종 안에서만 쓴다.
- 리서치 API 는 **오류로 중단하지 않는다.** 4xx 는 모르는 워크스트림/상태/빈 입력일 때만이다.
  예상 못 한 예외도 200 + `partial-continue` + Gap Log 로 넘긴다 (`research_router.py:234~243`).

### 8.3 정직성

| 하지 말 것 | 대신 |

### 9.3 링크 규칙 이중 구현 — 왜 두 겹으로 막나

M7 에서 H10 이 본문 연결률을 점수로 재게 되면서 **같은 규칙이 두 곳에** 생겼다.

어긋나면 둘 중 하나는 거짓말이 된다. 그래서:

| 검사 | 방식 |
|---|---|
| `regress_ui.js` **6절** | 서버 없이 · 규칙의 모든 갈래를 건드리는 **15줄**을 양쪽에 넣어 줄 단위 대조. 파이썬 모듈을 **파일 경로로 직접** 실행한다(`python3 app/services/research/linkcheck.py` + stdin JSON) |

서버 없이 도는 회귀검사의 성질이 유지된다. 이 제약을 깨지 마라.

  ↳ 예외 — 그 값이 **장부에 있으면** 세는 대상에 넣는다 (linkcheck.py:161-163
    `... and raw not in index and bare not in index`)
· 값이 D- 와 정확히 맞고 같은 줄에 그 지표 이름이 있을 때만 이었다고 센다
  ↳ 예외 — 지표 이름이 없어도 **후보가 딱 하나이고 뒤에 단위가 붙으면** 잇는다
    (linkcheck.py:176-177 "단위가 붙은 유일한 후보" · 단위 = 조·억·%·배·원·점·지수·p·pp)
· 값이 같은 D- 가 둘 이상이면 잇지 않는다
```

> 위 두 예외를 빠뜨리고 규칙을 재구현하면 **H10 증거 추적성 15점 중 5점**이 달라진다.
> `static/assets/research.js:652-654` 에도 같은 두 갈래가 있다 — 고칠 때 반드시 함께 고쳐라.

값 색인(`build_value_index`)은 서버가 리포트에 쓴 **표기법 그대로** 열쇠를 만든다 —

  IND-TP `proposal.top_pick`. `knowledge/technical.py` 의 `SIGNAL_BUY` 는 **사장 모듈**이라 쓰지 않는다.

  이야기는 숫자 하나" 가 된다). 시나리오는 색만으로 방향을 말하지 않는다 (화살표 ▲▼▬ 를 함께).
