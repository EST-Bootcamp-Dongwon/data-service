## 0. 왜 Minor(+0.1) 인가

**Context Pack 계약이 그대로다.** `C0`~`C6` · `logs` · `stage_result` 21필드 중 어느 것도
더하거나 빼거나 이름을 바꾸지 않았다. M8 이 새로 만든 것은 전부

- **확장 자리** — `CX_workstream.charts`(N84) · `CX_workstream.headline`(N86)

- **새 저장소·새 API** — `data/report_index.db`(N85) · `POST /api/research/export/html`(N88)

v2.0 이 Major 였던 이유(스키마 변경 · 제품 약속 축소 · 아키텍처 규칙 신설)에 해당하는 것이
하나도 없다. 그래서 **Minor** 다.

## 3. Context Pack 확장 (계약은 안 건드렸다)

```
CX_workstream
  ├─ analysis        (기존)
  ├─ charts    ★M8   차트 명세마다 그릴 계열 — charts.build()
  │    { id, kind, title, chart_type, unit, axis, categories, series,
  │      table, note, sources, data_ids, drawable, reason }
  ├─ headline  ★M8   리포트 표지 — headline.build()
  │    { workstream_id, target, as_of, verdict, metrics[], scenarios,
  │      axes[], evaluation, note, disclaimer }
  └─ report          (기존) + tables[] ★M8 + pages[].table_keys[] ★M8
```

`kind` 는 열 가지다 — `bar-h` · `bar` · `bar-line` · `line` · `scatter` · `range` ·
`radar` · `timeline` · `signal` · `stat`.

**`C4_visual` 은 손대지 않았다.** 공통계약이 정한 모양이라 확장은 `CX_workstream` 에만 했다.

## 7. 제품 약속에 손댄 것 — 없다

v2.0 이 축소한 약속("리포트의 **모든** 수치가 근거 링크")은 **그대로 유효하고 그대로
축소돼 있다.** M8 은 그 비율을 건드리지 않았다 (43% · 18% · 25% · 7% 그대로).

새로 내건 약속은 하나뿐이고, 실측으로 뒷받침한다:

> **자연어 검색 top1 은 75% 다.** 1위가 늘 맞지는 않는다 — 사업 설명이 비슷하면 역할이
> 달라도 가까이 놓인다 (`자동차 완성차 제조` 1위가 현대모비스라는 부품사). 그래서 화면은
> 순위와 함께 **왜 그 종목이 나왔는지(원문 조각)** 를 반드시 보여 준다.

## 8. 결정론(§1.1)과의 경계 — 이번에 못박은 것

사용자가 "종목코드가 아니라 이름·자연어로도 찾아지는 실제 검색" 을 골랐으므로,
`§1.1 같은 종목·같은 기준일이면 같은 결과` 와 부딪히는 지점을 먼저 갈랐다.

| | 무엇 | 결정론 |
|---|---|---|
| 리서치 파이프라인 | H02 가 **종목코드로 직접** 색인을 집는다 | ✅ 그대로 — 색인은 빌드타임 고정 |
| 자연어 검색 | 질의 1건만 런타임 임베딩 | ⚠️ 런타임이지만 **리포트 수치에 안 들어간다** |

- 색인이 빌드타임에 얼어 있으므로 **같은 질의는 같은 순위**를 낸다. 런타임에 달라질 수
  있는 것은 HuggingFace 가 살아 있느냐뿐이고, 죽으면 이름 검색으로 떨어지며
  `degraded=true` 로 **밝힌다**.
- 근거 `location` 에 **"원문 색인 &lt;빌드시각&gt; 기준"** 이 실려, 오래된 색인을
  오래되었다고 말한다.
