## 4. 깨지는 변경 (breaking)

**v1.0 스키마로 만든 Context Pack 을 M7 코드에 넣으면 어떻게 되는가**를 실제 코드 경로로 적는다.
전제: `research_router.run_step` 은 **예상 못 한 예외도 200 + `partial-continue` + Gap Log** 로 넘긴다 (`research_router.py:234-243`). 그래서 아래 어느 것도 **500 이 나지 않는다** — 대신 **조용히 낮은 값이 나온다**. 그게 더 위험하다.

### 4.1 Context Pack 스키마

| 변경 | 도입 | 이전 팩(v1.0 스키마)을 새 코드에 넣으면 |
|---|---|---|
| **`CX_workstream` 블록 추가** | N36 (M4) | `contracts.ensure_pack()` 이 빠진 블록을 `{}` 로 채워 주므로 **KeyError 는 안 난다**. 하지만 `stages._stashed()` 가 전부 `None` 을 돌려준다 → 산업 계열 H02·H03 은 `downgrade()` + `partial-continue`("산업이 확정되지 않아 정규화할 것이 없다"), H09·H10 은 `report`·`red_team`·`analysis` 를 못 찾아 **0건 기준으로 채점**한다. 200 은 나오고 리포트는 사실상 빈다 |

- **M5 → M6 은 하네스가 안 바뀌었다.** M6 는 UI 마일스톤이라 팩이 그대로다(팩 크기 0.2~0.4KB 차이는 `as_of` 등 문자열 길이 차). M6 가 새로 만든 것은 **연결률과 H10 총점을 처음 화면에 띄운 것**이고, 그때 두 문제가 드러났다 — 연결률 0~14%(N67) 와 **네 작업 전부 100/100 A**(N71).
- **M7 의 H10 이 내려간 것이 정상이다.** 루브릭만 바꿨을 때 네 작업이 전부 **B** 로 떨어졌다 (CORP-R 83.6 · CORP-TP 84.0 · IND-R 86.1 · IND-TP 78.7 — **작업 도중에 잰 값이고 지금 저장소로는 재현되지 않는다 → §5.2 각주**). 그동안 만점이던 것이 **실제로는 만점이 아니었다**는 뜻이다. 오른쪽 M7 칸은 그 지적을 실제로 고친 뒤의 값이다.

### 5.3 IND-TP 가 여전히 B 인 이유 — 숨기지 않고 적는다

리포트 8장 중 절반이 순위표인데 `1위 SK하이닉스 · adjusted 4.6 · observed 4.6 · coverage 100%` 의 세 수치 중 **되짚을 수 있는 것은 `coverage` 하나뿐**이다.

adjusted score 의 입력이 원시값이 아니라 **후보군 안 백분위(0/3/5 앵커)로 범주화된 값**이라, D- 를 붙여도 원값으로 되짚어지지 않는다. **없는 사슬을 만드는 대신** 원천 지표(`r250`·`roe`·`per`·`pbr`·`market_cap`)를 CALC- 의 **입력으로만** 달았다. `coverage` 는 "어느 지표가 있었나" 를 그대로 재는 값이라 D- 로 올렸다.

이 사실이 **점수(증거 추적성 10/15)와 화면 문장에 그대로 드러난다.** 그것이 이 루브릭이 하려는 일이다.

**작업량이 M6 에 맞먹어서 사실상 마일스톤 하나다.** M6·M7 과 섞으면 셋 다 어중간해진다.

| | 내용 |
|---|---|
| 풀려는 문제 | 원문(0.8MB ZIP) 내려받기가 서버리스 60초를 넘겨 **배포본에서 꺼져 있다**(N41) → slot 4·5·7 이 비어 리포트가 로컬 14장 → 배포본 11장 |
