## 3. 전처리 명세

> 기획서 §1의 "데이터 전처리가 확실해야 시계열 분석이 정확하다"를 구체화한 부분이다.
> **전처리 결과는 그 자체로 `stage_result`에 실린다.** 무엇을 어떻게 손봤는지 리포트에 남는다.

### 3.1 파이프라인

```
원본 OHLCV
  │
  ├ P1 거래일 정렬     휴장일 제거 · 거래소 캘린더 기준 재색인
  ├ P2 결측 처리       연속 결측 3일 이하 → 전일종가 이월(ffill) / 초과 → 구간 절단 + G-DATA
  ├ P3 이상치 검사     |로그수익률| > 5σ 또는 ±30% → 플래그 (제거 안 함, 표시만)
  ├ P4 액면·배당 조정  yfinance auto_adjust=True 사용, 조정 여부를 D- 레코드에 기록
  ├ P5 통화·단위       KRW/USD 명시 · 억/조 환산은 표시 계층에서만
  └ P6 품질 리포트     아래 표 생성
```

### 3.2 품질 리포트 필드

| 필드 | 내용 |
|---|---|
| `rows_raw` / `rows_clean` | 처리 전후 행 수 |
| `date_first` / `date_last` | 실제 데이터 범위 |
| `missing_days` | 결측 거래일 수 · 목록 |
| `filled_days` | ffill로 메운 일수 |
| `outliers` | 이상치 날짜·수익률 목록 |
| `gaps_emitted` | 발행한 Gap 코드 |
| `coverage_ratio` | `rows_clean / 기대 거래일수` |
| `verdict` | `usable` \| `usable-with-caveat` \| `insufficient` |

`coverage_ratio < 0.9`면 `usable-with-caveat`, `< 0.6`이면 `insufficient` → 시계열 모델링을 건너뛰고 `partial-continue`로 넘긴다 (GIC 불변원칙 §2-2).

### 3.3 이상치를 제거하지 않는 이유

주가의 극단 수익률은 대부분 **진짜 사건**(실적 발표, 유상증자, 급등락)이다. 제거하면 리스크를 과소평가한다. 따라서 **표시만 하고 모델에는 그대로 넣되**, 해석 카드의 `limitation`에 "표본에 ±N% 이상 변동일 M건 포함"을 적는다.

## 4. 시계열 엔진 명세

전부 `numpy` + `pandas`만 쓴다. `scipy`·`statsmodels` 금지 (D3).

### 4.1 모듈별 계약

| 모듈 | 함수 | 입력 → 출력 | 근거 강의 |
|---|---|---|---|
| `transform` | `log_returns(px)` | 종가 → 로그수익률 | 05-6 |
| | `difference(x, d)` | 시계열 → d차 차분 | 05-10 |
| `decompose` | `classical(x, period)` | → `{trend, seasonal, resid}` (중심이동평균) | 05-4 |
| `stationarity` | `adf(x, maxlag)` | → `{stat, crit_1/5/10, lag, verdict}` | 05-10 |
| `correlogram` | `acf(x, nlags)` | → `{values, conf_band}` (Bartlett) | 05-7 |
| | `pacf(x, nlags)` | → `{values, conf_band}` (Durbin-Levinson) | 05-8 |
| `models` | `fit_ar(x, p)` | OLS → `{coef, sigma2, aic, bic}` | 05-8 |
| | `fit_arima(x, p, d, q)` | Hannan-Rissanen 2단계 → 동일 | 05-9 |
| | `random_walk(x)` | 벤치마크 (drift 포함) | 05-6 |

| | `direction_prob(model, h)` | → 상승확률 (%) | — |
| | `scenarios(model, h)` | → Bear/Base/Bull + 트리거 | 08-14 |
| `backtest` | `walk_forward(x, model, folds)` | → `{rmse, mae, hit_rate, vs_rw}` | 04 |

### 4.2 ADF 임계값 (하드코딩 대상)

`scipy` 없이 구현하므로 MacKinnon(1994) 응답표면 계수를 상수로 둔다. 상수 검정(constant only, 표본 크기 보정 포함) 기준:

| 유의수준 | τ 임계값 (N→∞) |
|---|---|
| 1% | −3.43 |
| 5% | −2.86 |
| 10% | −2.57 |

표본 크기 보정항까지 넣어 `stationarity.py`에 표로 둔다. **근사값임을 코드 주석과 리포트 `limitation`에 명시한다.**

### 4.3 ARIMA — Hannan-Rissanen 2단계

MLE(scipy.optimize)를 못 쓰므로 OLS 두 번으로 대체한다.

```
1단계  고차 AR(k) 적합 (k ≈ ln(n)²) → 잔차 ê 추정
2단계  y_t 를 [y_{t-1..t-p}, ê_{t-1..t-q}] 에 OLS 회귀 → (φ, θ) 추정
3단계  잔차 백색잡음성 검사 (Ljung-Box 근사) → 실패 시 차수 재탐색
```

MLE보다 효율이 낮다. 그래서 **항상 확률보행과 백테스트로 비교하고, 못 이기면 리포트에 그대로 적는다** (기획서 D6).

### 5.3 stage_result 봉투

GIC 공통계약 §7의 YAML 스키마를 **필드명 그대로** JSON으로 옮긴다. 필드를 추가하지도 빼지도 않는다. 그래야 나중에 4차 루프 엔지니어링을 붙일 때 계약이 깨지지 않는다.

### 5.4 워크스트림별 차이

| 작업 | 세분화되는 상태 | 전용 판단 규칙 | 데이터 충분도 |
|---|---|---|---|
| **CORP-R** 기업리서치 | `H03` → 회계기간·재무·피어 정규화 3단 | 피어 선정(업종+시총 밴드) · 밸류에이션 멀티플 · 약한 논리 시 밸류에이션 차단 | 🟢 높음 (DART + yfinance) |
| **CORP-TP** 기업TopPick | `H04` → 12개월 이벤트 · Quick Score | 점수 방향성 · 자료 충분성 · Proceed/Watch/Drop 임계값 | 🟢 높음 (DART 공시) |
| **IND-R** 산업리서치 | `H04` → 밸류체인 · 시장·수급 · 사이클 | 시장 정의 고정 · CAGR 비교가능성 · 사이클 국면 판정 | 🟡 중간 (KRX 업종 + KOSIS) |
| **IND-TP** 산업TopPick | `H04` → 점수 · penalty · 민감도 | 후보 완전성 · 가중치 고정 · missing penalty · 순위 안정성 | 🟡 중간 |

산업 계열(IND-*)은 밸류체인 데이터가 공공 API에 없다. **KRX 업종코드 + KOSIS 산업생산지수 + DART 표준산업분류**로 조립하고, 부족분은 `G-SCOPE`로 명시한 뒤 조건부 결과를 낸다. 품질을 속이지 않는 것이 GIC 불변원칙이다.

### 5.5 Red Team 자동 생성 규칙 (`H07`)

LLM 없이 반대 근거를 만드는 방법 — **규칙으로 만든다.**

| 주장 유형 | 자동 반대 검사 |
|---|---|
| "매출이 성장했다" | 환율 기여 분리 여부 · 물량/가격 분해 가능 여부 → 불가 시 `E-CAUSAL` |
| "저평가 상태다" | 피어 대비 성장률·마진 차이 확인 → 차이가 크면 "디스카운트에 이유가 있음" 반증 제시 |
| "추세가 상승이다" | 확률보행 귀무가설 대비 유의성 · 표본 구간 변경 시 뒤집히는지 검사 |
| "실적이 개선됐다" | 일회성 항목 · 회계기준 변경 · 기저효과 확인 |
| 모든 상관관계 주장 | 경쟁 가설 최소 1개 + 중간 KPI 요구 (GIC §12.1 "분석 논리" 배점 15) |

각 검사는 통과·실패·판정불가를 반환하고, 실패 시 해당 주장의 `confidence`를 한 단계 내린다.
