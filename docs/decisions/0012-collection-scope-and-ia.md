# ADR-DS-0012: 수집 범위를 여섯 갈래로 정하고 화면을 원천이 아니라 자료 종류로 가른다

## 상태

채택됨 (2026-08-23)

## 맥락

랜딩 화면 · README · 사이드바 셋이 **같은 질문 하나**에 매달려 있었다 — 이 레포는 무엇인가.
2026-08-22 에 사용자가 "범위가 미확정이니 미룬다"고 명시했고, 2026-08-23 에 범위를 정했다.

지금 `/` 의 순서가 그 미정 상태를 그대로 드러낸다.

```
대시보드(지수·환율) → 시장 온도 → 최근 리서치 리포트(빈 자리) → 데이터 상태(맨 아래)
```

**이 레포가 실제로 하는 일**(9원천 수집·보관·제공)이 맨 아래이고, **아직 없는 기능**
(리서치 리포트 · `dashboard.html:69-75` 의 `placeholder`)이 중간을 차지한다.

사이드바도 같다. `shell.js` 의 `NAV` 는 화면을 **원천별**로 늘어놓는다 —
`KRX 시세` · `KOSIS 통계` · `야후 파이낸스`. 사용자가 찾는 것은 "야후에서 온 것"이 아니라
"삼성전자에 관한 것"인데, 그 축이 정보구조에 없다.

### 실측 — 크롤링은 0 에서 시작한다 (2026-08-23)

| | 실물 |
|---|---|
| 클라이언트 9종 | **전부 정형 API 다.** DART · KRX · KOSIS · ECOS · FRED · FSS · 야후 · HF(추론) |
| HTML 파싱 경로 | `scripts/kosis_rss.py`(RSS) · `scripts/build_us_master.py` **둘뿐이고 앱 밖이다** |
| `beautifulsoup4` | `[project.optional-dependencies].scripts` 에만 있다. **런타임 의존성이 아니다** |
| 화면 10개 | 원천별로 갈려 있다. 자료 종류(뉴스·공시·보고서)로 묶인 화면은 **하나도 없다** |
| 검색 | `/api/search` · `/api/search/semantic` 이 있지만 **사업보고서 원문 색인 전용**이다 |
| 담을 그릇 | `clip` 표 DDL 이 `news`·`filing`·`dataset`·`report`·`memo` 5종을 받게 **이미 서 있다** (ADR-DS-0008) |
| 그릇을 쓰는 코드 | **없다.** `app/repositories/clip_store.py` 가 아직 없다 |

즉 있는 것은 **정형 API 9종과 빈 표 하나**다. 크롤링 코드는 앱 경로에 존재하지 않는다.
"크롤링 기능을 전부 포함한다"는 말은 **기존 것을 재배치하는 일이 아니라 새로 짓는 일**이다.

## 결정

### 1. 정체성 — 한 문장을 정하고 세 곳이 같은 문장을 쓴다

> **흩어져 있는 국내 투자 정보를 한 곳에 모아 두는 수집·보관·조회 서비스.**
> 시세·통계는 정형 API 로, 공시·뉴스·커뮤니티는 수집으로 모으고, **기업과 산업**을 축으로 되찾는다.

이 문장을 `README.md` 첫 줄 · 랜딩 히어로 · `app/main.py` 의 OpenAPI `description` 이 공유한다.
**셋이 어긋나면 그것이 곧 결함이다** — 정체성은 한 군데서만 바뀐다.

⚠️ 리포트를 **만드는** 것은 여전히 이 레포의 일이 아니다 (ADR-DS-0007). 경계는 그대로다.
모으는 것까지가 여기이고, 그것으로 무엇을 쓰는가는 `research-service` 다.
(2026-09-15 갱신: `research-service` 는 개발하지 않기로 했다 — 리포트 파이프라인은 이 레포에 남는다. ADR-DS-0007 갱신 블록 참고)

### 2. 수집 대상은 여섯 갈래다. 전부 범위 안이다

| # | 갈래 | 무엇을 모으나 | `clip.kind` | 착수 |
|---|---|---|---|---|
| ① | **공시** | DART 정기·수시공시 목록과 원문 | `filing` | **1차** |
| ② | **정기보고서** | 사업·반기·분기보고서 본문(부문별 매출·점유율·생산능력) | `filing` | **1차** |
| ③ | **뉴스** | 제목·링크·언론사·발행일 | `news` | 2차 |
| ④ | **커뮤니티** | 종목토론방·게시판의 제목·링크·집계 | `post` (새 값) | 3차 |
| ⑤ | **동영상** | 제목·링크·채널·게시일 **링크까지만** | `video` (새 값) | 3차 |
| ⑥ | **시세·통계** | 기존 9원천 (크롤링이 아니라 정형 API) | — (`ohlcv` 등) | 이미 있음 |

**①② 를 먼저 한다.** 근거는 셋이다.

- `dart_data.py` · `dart_report.py` 두 클라이언트가 **이미 있고**, `build_report_index.py` 로
  전종목 2,489곳 원문 색인을 만들어 본 실적이 있다.
- OpenDART 인증키가 `.key` 에 **이미 배치돼 있다** (`_dart_status()` 가 확인한다).
- 공공데이터라 **저작권·이용약관 회색지대가 없다.** ③④⑤ 는 그렇지 않다.

⚠️ `clip_kind_ck` 제약이 지금 5값(`news`·`filing`·`dataset`·`report`·`memo`)으로 **고정돼 있다.**
④⑤ 에 새 값을 쓰려면 그 CHECK 을 고쳐야 하고, **이 레포에는 마이그레이션 러너가 없다**
(ADR-DS-0011 맥락). 그러니 ④⑤ 착수 전에 값을 추가하는 것이 아니라, **①② 를 적재하기 전
`03-clip.sql` 에 여섯 값을 한 번에 넣어 둔다.** 빈 볼륨에서 한 번 서면 그다음은 전면 재적재다.

> ✅ **2026-08-23 에 넓혔다** (ADR-DS-0014 §8 · S3 적재 직전).
> ⚠️ 위에서 "여섯 값"이라고 적었지만 **실제로는 일곱**이다. 갈래가 여섯이고 그것이
> `kind` 네 값(`filing`·`news`·`post`·`video`)으로 접히며, `dataset`·`report`·`memo` 셋은
> 갈래가 아니라 **내가 담는 것**이라 원래부터 있었다(ADR-DS-0008). 갈래 수와 값 수는 1:1 이 아니다.
> 링크형 제약(`clip_link_needs_url_ck`)도 함께 넓혔다 — §3 이 ④⑤ 를 링크까지만 으로 못박았으므로
> URL 없는 커뮤니티 글·동영상은 담을 것이 없다는 뜻이 된다.

### 3. 본문을 저장하지 않는 원칙을 여섯 갈래 전부로 넓힌다

ADR-DS-0008 이 뉴스에만 걸어 둔 규칙(**링크·제목·출처·발행일·내 메모까지**)을
③④⑤ 전부에 적용한다. 예외는 **①② 하나** — DART 공시·보고서 원문은 공공데이터이고
OpenDART 가 기계 판독용으로 명시적으로 제공한다.

④⑤ 는 여기에 더해 **착수 시점에 `robots.txt` 와 이용약관을 먼저 읽고 그 결과를 ADR 로 남긴다.**
읽지 않고 짜기 시작하지 않는다.

### 4. 화면은 자료 종류로 가른다. 원천별이 아니다

사이드바를 다음 여섯 묶음으로 재편한다. **"수집 자료" 가 두 번째 묶음**이라,
사이드바를 보는 것만으로 이 서비스가 무엇인지 읽힌다.

| 묶음 | 항목 |
|---|---|
| (무제목) | 대시보드 · **통합 검색**(예정) |
| **수집 자료** | **공시·보고서**(예정) · **뉴스**(예정) · **커뮤니티**(예정) · **동영상**(예정) · **보관함**(예정) |
| 시장 데이터 | 시장 상세 · 종목 조회 · KRX 시세 · 야후 파이낸스 · KOSIS 통계 |
| 분석 | 퀀트 분석 · 시계열 분석 |
| 리서치 | 기업 리서치 · 기업 Top Pick · 산업 리서치 · 산업 Top Pick |
| 시스템 | 데이터 상태 · 프로젝트 안내 · 실습 아카이브 · API 문서 |

**예정 항목을 지금 메뉴에 올린다.** `shell.js` 의 `soon: true` 가 링크를 죽이고 '준비중'을
글자로 밝히는 장치를 이미 갖고 있다(`shell.js:22-24`). 앞으로 무엇이 생기는지가 정보구조의
일부라는 것이 이 파일의 원래 방침이고, 그 방침을 여기서 처음 크게 쓴다.

### 5. 검색 허브를 자료 화면 **위**에 둔다

기업명·종목코드·산업명으로 검색하면 **그 대상에 걸린 여섯 갈래가 한 화면에** 모인다.
갈래별 화면은 그 아래 단계다. 지금의 `/api/search` 는 사업보고서 원문 전용이므로,
허브는 **새 경로**(`/api/hub/*` 가 아니라 기존 `/api/search` 를 확장)로 간다 — 결정은 착수 때.

### 6. 필터 축 셋을 모든 수집 화면이 공유한다

- **기간** — 일 · 월 · 연 (`clip.occurred_at` 기준. `saved_at` 은 "내가 언제 담았나" 축이라 따로다)
- **기업** — `clip.security_id`
- **산업** — `clip.industry_code` (KSIC 접두어 `LIKE '26%'`)

셋 다 `clip` 인덱스가 이미 받는다(`clip_screen_kind_idx` · `clip_industry_idx` · `clip_security_idx`).
**축을 늘리려면 인덱스를 늘려야 하므로, 넷째 축을 임의로 더하지 않는다.**

### 7. 랜딩을 다시 짠다 — 하는 일이 맨 위다

```
① 히어로       이 서비스가 무엇인가(§1 문장) + 수집 갈래 6개 현황 타일
② 데이터 상태   지금 무엇을 쓸 수 있는가 (맨 아래 → 두 번째로)
③ 시장 카드     지수·환율·금리
④ 시장 온도
⑤ 최근 리서치   (빈 자리인 채로 맨 아래)
```

빈 자리를 **없애지 않고 맨 아래로 내린다.** 비어 있음을 숨기지 않는 것이 이 화면의 방침이고
(`dashboard.html:31-35` 의 `.placeholder` 주석), 리서치는 실제로 계획에 있다.

### 8. 저장은 Postgres 전환(S3~S5)이 끝난 뒤에 시작한다

수집 표를 SQLite 에 새로 파지 않는다. ADR-DS-0011 의 S3 → S4 → S5 를 먼저 끝내고,
`clip` 을 그 위에 얹는다. **지금 SQLite 에 파면 나중에 두 번 옮긴다.**

즉 실행 순서는 이렇게 고정된다.

```
S3 적재기 → S4 어댑터 → S5 기본값 뒤집기 → clip_store + ①② 수집 → 화면 → ③ → ④⑤
```

⚠️ **화면(§4·§7)과 README 는 이 순서를 기다리지 않는다.** 저장과 무관하게 지금 선다.
그래서 이 ADR 은 화면부터 적용하고, 수집 구현은 S5 뒤로 둔다.

### 9. 이 레포는 개인 프로젝트로 완성한다. 팀 프로젝트는 별도 레포다

팀원을 모집한 뒤의 확장은 **다른 폴더 · 다른 저장소**에서 한다. 이 레포는 그때 **가져다 쓰는
원본**이 되고, 여기에 팀 협업용 장치(브랜치 전략 · 이슈 템플릿 · 다인 배포)를 미리 넣지 않는다.

그 귀결로 **문서가 이 레포 밖에서도 읽혀야 한다.** 미러 규약은 ADR-DS-0013 에 있다.

## 근거

**원천별 화면이 원천의 수만큼 늘어난다.** 지금 5개 화면(krx·kosis·yf·stock·quant)이 원천
4곳을 덮는다. 여기에 뉴스·커뮤니티·동영상 크롤러가 각각 여러 사이트를 물면 화면이 사이트
수만큼 늘어난다. 사용자가 말한 "여러 크롤링 사이트를 아우르는 하나의 사이트"는 정확히
그 반대이므로, 축을 **자료 종류 + 대상(기업·산업)** 으로 돌린다.

**`clip` 표가 이미 그 축으로 서 있다.** ADR-DS-0008 이 "화면별로 나눠 본다"를 가장 잦은
질의로 보고 `kind` + `screen` 을 인덱스 선두에 뒀다. §4·§6 은 그 설계를 화면 쪽에서 마저
쓰는 것이고, **새 저장 설계를 요구하지 않는다.**

**착수 순서 ①② 우선의 근거는 인증키와 실적이다.** DART 는 키가 배치돼 있고 클라이언트가
둘 있으며 색인 빌드 실적(2,489곳 · 21분)이 있다. ③ 네이버는 키는 있으나 **일일 쿼터**가 있어
호출 상한 설계가 선행하고, ④⑤ 는 이용약관 확인이 선행한다. **선행 조건이 없는 것부터 한다.**

**저장을 뒤로 미루는 근거는 마이그레이션 러너의 부재다.** `sql/init/*.sql` 은 빈 볼륨 최초
기동에만 돈다(`01-schema.sql:3-5`). 적재를 시작한 뒤 컬럼 하나를 고치는 것이 전면 재적재이므로,
**적재를 시작하는 시점을 최대한 늦추는 것이 되돌릴 수 있는 유일한 방법**이다.

## 결과

**쉬워지는 것**

- 랜딩·README·사이드바 셋이 §1 한 문장에 걸린다. 정체성이 한 군데서만 바뀐다.
- 크롤러가 늘어도 화면이 늘지 않는다. 새 사이트는 갈래 하나 안의 **출처 하나**로 들어간다.
- 예정 항목이 메뉴에 있으므로, 다음에 무엇을 할지가 코드가 아니라 화면에 적혀 있다.

**어려워지는 것**

- **메뉴에 '준비중'이 다섯 개 걸린다.** 지금 상태로는 사이드바 절반이 비어 보인다.
  §2 의 착수 순서대로 채워 나가는 것 외에 이것을 감출 방법은 없고, 감추지 않는다.
- `clip_kind_ck` 를 여섯 값으로 **미리** 넓혀야 한다(§2 ⚠️). 아직 쓰지 않는 값이 DDL 에
  먼저 들어가는 모양이 되는데, 러너가 없는 상태에서는 이쪽이 싸다.
- 검색 허브(§5)가 지금의 `/api/search`(사업보고서 원문 전용)와 **이름이 겹친다.** 확장할지
  새 네임스페이스를 팔지는 착수 때 결정해야 하고, 그때 ADR 번호를 하나 더 받는다.
- ③④⑤ 는 각각 **선행 조사**가 붙는다(쿼터 설계 · `robots.txt` · 이용약관). 그 조사 없이
  코드를 먼저 짜지 않기로 했으므로, 착수 시점이 조사에 매인다.
