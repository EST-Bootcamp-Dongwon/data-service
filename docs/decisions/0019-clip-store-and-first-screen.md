# ADR-DS-0019: 자료 보관함을 Postgres 위에 세우고 `/stock` 한 갈래를 끝까지 잇는다

## 상태

채택됨 (2026-08-25)

## 맥락

ADR-DS-0008 이 자료 보관을 **한 표 `clip` + `kind`** 로 정하고 DDL 까지 세웠다.
ADR-DS-0012 가 수집 갈래를 여섯으로 확정하고 **착수 시점을 "S5 뒤"** 로 못 박았다 —
그전에 SQLite 에 표를 새로 파면 나중에 두 번 옮기기 때문이다.

S5 가 끝났으므로(ADR-DS-0018) 그 문이 열렸다. 그리고 이 레포의 완료 조건 목록에는
**"자료 보관이 동작한다"** 가 아직 빈칸으로 남아 있다. DDL 은 2026-08-23 에 섰지만
그 표를 읽고 쓰는 코드는 **한 줄도 없었다.**

정체성 문장이 말하는 여섯 갈래 중 지금 도는 것은 시세·통계 하나뿐이다. 나머지 다섯은
사이드바에 `soon` 으로 걸려 있다 — 감추지 않기로 했으므로 그 빈자리가 계속 보인다.

### 무엇부터 만들 것인가

세 덩어리다 — ① 저장소+API · ② 수집(DART 공시·네이버) · ③ 화면. 순서를 고를 때
기준은 하나였다. **"동작한다"를 가장 짧게 증명하는 절단면이 어디인가.**

②를 먼저 하면 표는 자동으로 차지만 사람이 볼 자리가 없다. ①만 하면 계약은 서지만
여전히 아무도 못 쓴다. 그래서 **①→③ 을 한 갈래로 세로로 자른다.**

## 결정

### 1. `clip` 은 Postgres 전용이다 — 배포본은 S6 뒤에 살아난다

SQLite 에 같은 표를 파는 선택지는 **레포 규칙이 이미 막고 있다**(AGENTS.md ·
ADR-DS-0012 §8). 그래서 이 기능은 **로컬에서 먼저 산다.**

배포본은 `DATABASE_URL` 이 없어(그것을 주는 것이 S6) 담기·목록 모두 거절된다.
⚠️ 그 거절은 **왜 안 되는지와 언제 되는지**를 함께 말한다 — 화면 패널이 잠기면서
"지금은 담을 수 없습니다 — 저장소에 못 붙었다" 와 처방을 그대로 싣는다.

### 2. 막는 것은 환경이 아니라 **능력**이다

`clip_store.availability()` 는 `APP_ENV` 를 보지 않는다. **표에 붙어 보고** 판단한다.

```text
붙는다 + clip 표가 있다   → 쓸 수 있다
못 붙는다                 → 이유 + db.unreachable() 의 처방
붙는데 표가 없다          → 빈 볼륨으로 다시 띄우라는 처방 (sql/init 은 최초 1회만 돈다)
```

그래야 Supabase 를 붙인 날 이 함수를 **고치지 않아도** 배포본에서 그대로 살아난다.
ADR-DS-0017 이 갱신 API 에서 세운 원칙과 같은 자리에 같은 모양으로 둔다.

⚠️ **"언제 되는지" 는 `availability()` 가 직접 붙인다** (`WHEN_IT_WORKS`). 처음에는
`db.unreachable()` 의 `extra` 에만 두었는데, **배포본에서는 그 줄이 실리지 않았다**(실측) —
`DATABASE_URL` 이 아예 없어 접속을 시도하기 **전에** `settings` 가 `RuntimeError` 를 던지고,
`_fetch()` 는 `OSError` 만 감싸기 때문이다. 그런데 "언제" 가 가장 필요한 곳이 바로 배포본이다.
처방이 *"무엇을 하라"* 로만 끝나면, 그 무엇을 할 수 없는 사람에게는 여전히 막다른 길이다.

### 3. 경로는 배포본에서도 등록한다. 실행만 거절한다

`/api/clips` 다섯 경로는 어디서든 등록된다. 조건부 등록을 하면 계약 스냅샷이 환경에
따라 갈리고, 무엇보다 **왜 안 되는지 설명할 자리가 사라진다.**

⚠️ 예외가 하나 있다 — **`GET /api/clips/status` 만은 `503` 을 내지 않는다.**
화면이 버튼을 잠글지 정하려면 "왜 못 쓰는지" 를 200 으로 받아 볼 수 있어야 한다.
거기까지 503 이면 화면은 **이유 없이** 잠긴다.

### 4. `kind` 별 검증은 **라우터**에 둔다

`payload` 가 `jsonb` 라 DB 차원의 타입 검증이 없다. 공시를 담으면서 `rcept_no` 를
빠뜨려도 표는 받아 준다. 그러면 나중에 그 행으로 DART 원문을 되찾을 수 없는데,
빠졌다는 사실은 **되찾으려는 순간에야** 드러난다. 그래서 넣는 자리에서 막는다.

| kind | 반드시 있어야 하는 것 |
|---|---|
| `filing` | `payload.rcept_no` — 없으면 원문을 되찾을 수 없다 |
| `dataset` | `payload.source` · `payload.params` — 어떤 조건으로 뽑았는지 |
| `report` | `payload.run_id` — 어느 실행인지 |
| `memo` | `note` — 내용 없는 메모는 담을 것이 없다 |
| `news`·`post`·`video` | `url` (표도 막지만 여기서 먼저 막아 읽을 수 있는 422 를 낸다) |

⚠️ **DDL 이 이미 거는 것을 다시 걸지 않는다.** `clip_kind_ck`(일곱 값)와
`clip_link_needs_url_ck` 는 표가 지킨다. 두 벌로 걸면 한쪽만 고쳐진 채로 오래 간다.
대신 `tests/test_clip.py` 가 **DDL 파일을 직접 읽어** 코드의 어휘와 대조한다 —
두 벌이 아니라 한 벌이라는 것을 검사가 붙든다.

### 5. 중복은 오류가 아니다

같은 링크를 다시 담으면 **새로 만들지 않고 기존 것을 돌려주고** `created=false` 로 밝힌다.
사람이 두 번 누르는 것은 실수가 아니라 *"이미 담았나?"* 를 확인하는 행동이다.
`409` 로 막으면 화면이 그것을 오류로 그린다.

같은 기사를 알아보려면 URL 을 정규화해야 한다. 떼는 것 넷 —
**스킴 · `www.` · 추적 파라미터 · 프래그먼트**. 남는 질의는 **정렬**한다(같은 링크를
순서만 다르게 받는 일이 흔하다). 경로의 끝 슬래시는 떼되 **루트의 `/` 는 남긴다** —
떼면 호스트만 남아 서로 다른 사이트가 뭉친다.

⚠️ **네트워크를 타지 않는다.** 리다이렉트를 풀면 정확해지지만 이 함수가 느려지고
실패할 수 있게 된다. 담기는 사람이 버튼을 누르는 순간이라 그 비용을 지지 않는다.

⚠️ `url_key` 가 NULL 인 행(메모·스냅샷)은 부분 유니크에 걸리지 않아 **여러 번 담긴다.**
DDL 이 의도한 동작이다.

### 6. 산업은 자동 유도하고, 사람이 고치면 `manual` 로 잠근다

종목코드를 주면 `securities` 에서 `security_id` 와 `industry_code` 를 함께 푼다.
실측 — 2,875종목 중 **2,700(94%)** 이 산업코드를 갖고 있다. 나머지는 `None` 이고
그것이 정상이다(추정하지 않는다 · ADR-DS-0014).

⚠️ `reassign_industries()` 의 `WHERE industry_source = 'auto'` **한 줄이
`industry_source` 컬럼이 존재하는 이유 전부다.** 빠지면 사람이 고친 값이 조용히 사라진다.
검사가 그 문장을 붙든다.

### 7. 첫 화면은 `/stock` 이다

기업이 축이라는 정체성과 맞고, `security_id`·`industry` 가 그 화면에 이미 있어 자동
유도가 그대로 동작한다. 패널 하나에 **담기 + 목록 + 필터(종류·연월·태그·전체보기)** 를 넣었다.

⚠️ **해외 종목은 종목에 묶지 않는다.** 야후 티커(AAPL)는 `securities` 에 없어
`security_id` 가 NULL 이 되고, 그러면 "이 종목의 자료" 라는 말이 성립하지 않는다.
담기 자체는 되게 두되(거시 메모도 자료다) 목록을 전체 보기로 떨어뜨리고 그 사실을 적는다.

### 8. 접속 실패 처방은 `db.unreachable()` 한 곳에서 만든다

ADR-DS-0018 이 `krx_pg._fetch()` 안에 처방을 넣었는데, 보관함이 같은 것을 필요로 하면서
**두 벌이 될 뻔했다.** 공통(붙는 곳 · 띄우는 법 · 배포본이면 다른 안내)은 `db.py` 가
만들고 **되돌리는 법만** 부르는 쪽이 얹는다 — 그것은 저장소마다 다르다.

```text
시세   → "SQLite 로 되돌린다: STORE_BACKEND=sqlite"
보관함 → "보관함은 Postgres 에만 있다 — 배포본은 S6 뒤에 쓸 수 있다"
```

⚠️ `db.py` 는 위층을 부르지 않는다. `extra` 가 **문자열**인 것이 그 경계다.

### 9. 화면에서 보관함을 **먼저** 그린다

`/stock` 의 `render()` 는 요약·타일·차트·상관계수를 차례로 그린다. 보관함을 맨 뒤에
두었더니, 차트 라이브러리가 안 뜨는 환경에서 그 예외가 `search()` 의 `catch` 로
빠지면서 **보관함이 같이 죽었다**(jsdom 실주행 실측 — `matchMedia is not defined`).

담아 두는 것은 차트가 그려지는 것과 아무 상관이 없다. 그래서 `onStockResolved()` 를
`render()` **맨 앞**으로 옮겼다.

## 검증

### 저장소 왕복 — 실 DB 13항목

`clip` 표를 비우고 처음부터 잰다.

| | 결과 |
|---|---|
| 담기 · 산업 자동 유도 | `264` · `auto` · 삼성전자(`security_id` 458) |
| 같은 링크 다시 (`utm`·`fbclid`·끝 슬래시·`www` 만 다름) | **같은 행** · `created=false` |
| 메모 둘 | 서로 다른 행 (`url_key` NULL 이라 부분 유니크에 안 걸린다) |
| `payload` jsonb 왕복 | `{rcept_no, report_nm}` 그대로 |
| 산업 직접 수정 → 재유도 | `manual` 이 지켜졌다 (0건 덮음) |
| 필터 — 종류·연월·태그·검색어 | 전부 기대값 |
| 패싯 | 종류 3종 · 월 1개 · 태그 2개 |
| 삭제 후 | 0건 |

### API — 검증이 저장소보다 **앞에서** 막는가

| 보낸 것 | 결과 |
|---|---|
| 어휘 밖 `kind`(`tweet`) · 어휘 밖 `screen` | `422` |
| `news` 인데 `url` 없음 · `memo` 인데 `note` 없음 | `422` |
| `filing` 인데 `rcept_no` 없음 | `422` + **어느 열쇠가 없는지** 메시지에 |
| 모양이 맞는 본문 (DB 없는 검사 환경) | `503` ← 저장소 단계까지 갔다 |
| `GET /api/clips/status` (DB 없음) | **`200`** · `available=false` + 처방 + **언제 되는지** |

마지막 두 줄이 짝이다 — 전부 `422` 면 "검증이 다 막는다" 와 "저장소에 닿지 못한다" 가
구별되지 않는다.

### 화면 — jsdom 으로 `/stock` 을 실제로 돌린다

| | 결과 |
|---|---|
| 보관함 패널 | 살아 있음 (폼·목록 보임) |
| 범위 표시 | `— 삼성전자 (005930)` |
| 빈 목록 | "아직 담아 둔 것이 없습니다" |
| 폼을 채워 담기 | "담았습니다" · 1행 |
| 추적 파라미터만 다른 같은 링크 | "이미 담아 둔 것입니다" · **여전히 1행** |
| 필터 선택지 | 서버 패싯에서 채워짐 |
| 콘솔 오류 | 없음 |

⚠️ `조회 실패` 가 함께 뜨는데 이는 **jsdom 이 `matchMedia` 를 구현하지 않아서**이고
차트 경로의 일이다. 그 사실이 §9 의 근거가 됐다.

### 배포본 — 잠기되 설명한다

push 뒤 실제 배포본(`api-test-sable-phi.vercel.app`)에서 잰다.

| 경로 | 결과 |
|---|---|
| `/stock` | `200` — 화면은 뜨고 보관함 패널만 잠긴다 |
| `GET /api/clips/status` | **`200`** · `available=false` · `DATABASE_URL 이 없다…` + 포트 6543 안내 |
| `GET /api/clips?screen=stock` | `503` · 같은 처방을 `detail` 에 |

⚠️ 이 실측이 위 §2 의 `WHEN_IT_WORKS` 를 낳았다 — 첫 배포에서 "언제" 가 빠져 있었다.

### 검사

`invoke check` 초록 — **309 tests** (S5 의 275 에서 34 늘었다). 계약 스냅샷은
**추가 33줄 · 삭제 0** — 기존 계약이 하나도 바뀌지 않았다.

## 기각한 대안

**① `clip` 을 SQLite 에도 만들어 배포본에서 쓰게 한다.** 레포 규칙이 막는다 —
"지금 SQLite 에 표를 새로 파면 나중에 두 번 옮긴다". 그리고 두 저장소가 갈리는 순간
"담았는데 없다" 가 되는데, 그 고장은 사람의 기록을 잃는 종류라 가장 비싸다.

**② 중복 링크를 `409` 로 막는다.** 사람이 두 번 누르는 것을 오류로 그린다. §5.

**③ `kind` 별 검증을 DB `CHECK` 로 건다.** `jsonb` 안쪽을 제약으로 검사하면 규칙이
바뀔 때마다 마이그레이션이 필요한데 **이 레포에는 마이그레이션 러너가 없다**(01-schema.sql:3-5).
그리고 위반이 SQL 오류 메시지 안쪽에 숨어 사람이 고칠 곳을 못 찾는다.

**④ 별도 `/clips` 화면을 먼저 만든다.** 목록은 서지만 **담을 방법이 없어** 영원히 비어
있다. "동작한다" 를 증명하려면 담는 자리와 보는 자리가 같은 절단면에 있어야 한다.

**⑤ URL 정규화에서 리다이렉트를 따라간다.** 정확해지지만 담기가 네트워크에 매인다. §5.

## 결과

- 자료 보관이 **로컬에서 실제로 동작한다** — 담기·목록·필터·삭제·산업 보정
- 여섯 갈래 중 아직 **자동 수집은 0개**다. 사람이 손으로 담는 길만 열렸다
- 배포본은 잠겨 있고 **왜·언제**를 말한다. 푸는 것은 **S6**

### 남는 숙제

- **② 수집이 통째로 남았다** — DART 공시(`dart_data.fetch_disclosures` 는 이미 있다) ·
  네이버 검색 API(키는 배치 완료). ⚠️ 네이버는 **일일 쿼터**가 있어 호출 상한 설계가 먼저다
- **다른 아홉 화면에는 담기 버튼이 없다.** 패널을 공용 조각으로 빼는 것이 그다음이다 —
  지금은 `/stock` 안에 있다. 두 번째 화면을 붙일 때 빼는 것이 옳고, 지금 빼면
  쓰는 곳이 하나뿐인 추상이 된다
- **사이드바 '수집 자료' 다섯은 여전히 `soon`** 이다. 화면이 실제로 설 때 푼다
- **메모·태그 수정 UI 가 없다.** API(`PATCH`)는 있고 화면은 삭제만 붙였다
- `clip` 은 아직 **`securities` 없는 자료**(거시지표·산업 전체)를 잘 다루지 못한다.
  `industry_code` 를 직접 고르는 자리가 화면에 없다
