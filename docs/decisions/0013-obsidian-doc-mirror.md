# ADR-DS-0013: 문서를 Obsidian 볼트에 커밋 시점마다 한 방향으로 미러한다

## 상태

채택됨 (2026-08-23)

## 맥락

이 레포는 **개인 프로젝트로 완성하고, 팀 프로젝트는 별도 저장소에서 한다** (ADR-DS-0012 §9).
그러면 팀원을 모집하는 시점에 **"여기까지 했다"를 레포 밖에서 읽을 수 있어야 한다** —
저장소를 클론하지 않은 사람에게 결정 이력과 경계를 보여줘야 하기 때문이다.

사용자는 이미 Obsidian 볼트를 운영하고 있고, 그 볼트에는 규약이 서 있다.

| 볼트 실측 (2026-08-23) | 내용 |
|---|---|
| 경로 | `C:\Users\kik32\내 드라이브\Master_Obsidian` (구글 드라이브 동기화) |
| 규칙 문서 | `99_System/` 에 **셋** — `Vault Structure` · `Note Title Rules` · `Metadata Rules` |
| 프로젝트 자리 | `30_Projects/<프로젝트명>/` — `stock-coin-trade` · `credible-stock-research` 등이 이미 이 모양이다 |
| 기존 미러 방식 | `scripts/workspace_mirror_builder.py` 등 **볼트 쪽 스크립트가 바깥을 긁어 온다** |
| 원칙 | Home.md: "원본은 건드리지 않고, 이 Vault에는 정리된 미러만 둔다" |

즉 **새 체계를 만들 필요가 없다.** `30_Projects/data-service/` 를 얹으면 된다.

한편 전역 규칙(`~/.claude/CLAUDE.md` §7.1)은 "문서는 로컬과 볼트 양쪽에 미러링하고
`docs/` 는 `.gitignore`" 라고 적혀 있다. **이 레포는 그 한 단계가 다르다** —
`docs/decisions/` 에 ADR 13개가 있고 전부 커밋된다. 결정 이력이 코드와 같은 커밋에 묶여야
"왜 이렇게 짰나"가 나중에 복원되기 때문이다. 그러므로 여기서는 gitignore 대신
**양쪽 다 보관**이 되고, 그것이 오히려 이중 보관이라는 목적에 맞는다.

## 결정

### 1. 한 방향이다 — 레포가 정본, 볼트는 미러

```
projects/data-service/  ──(미러)──▶  Master_Obsidian/30_Projects/data-service/
       ▲ 정본                              볼트 쪽 수정은 다음 동기화에 덮인다
```

볼트 쪽에서 고친 것은 **되돌아오지 않는다.** 그래서 미러본 첫머리에 그 경고와
정본 경로를 박아 넣는다. 양방향 동기화는 하지 않는다 — 충돌 해소 규칙이 필요해지고,
그 규칙이 틀리면 **어느 쪽이 정본인지 모르는 상태**가 되는데 그것이 가장 나쁘다.

### 2. 커밋 시점에 자동으로 돈다 (`post-commit` 훅)

수동 실행은 잊는다. `invoke check` 에 묶는 것도 하지 않는다 —
**검증 명령이 레포 밖에 쓰기를 하면 안 되기 때문이다**(같은 명령이 CI·다른 머신에서도 돈다).

`post-commit` 이 맞는 자리인 이유는 하나 더 있다: **커밋된 것만 미러된다.**
작업 중인 초안이 볼트로 새지 않고, 볼트 내용은 항상 어떤 커밋과 대응한다.
"버전 관리와 어긋나지 않는다"가 이 선택의 핵심이다.

- 훅은 **커밋을 절대 막지 않는다.** 실패해도 `|| true` 로 흘린다.
- 볼트 폴더가 없으면(다른 머신·CI) **조용히 건너뛴다.**
- 훅 설치는 `invoke hooks` 한 번. **`invoke preflight` 가 설치 여부를 확인해 알려 준다** —
  안 그러면 훅이 없다는 사실이 조용히 묻힌다.

⚠️ 이 레포는 **서브모듈**이라 `.git` 이 디렉터리가 아니라 gitdir 포인터 **파일**이다.
훅 자리는 `git rev-parse --git-dir` 로 찾는다. `.git/hooks` 를 그대로 쓰면 실패한다.

### 3. 무엇을 미러하나 — 넘겨줄 때 읽혀야 하는 것만

| 미러함 | 왜 |
|---|---|
| `README.md` | 현관 |
| `AGENTS.md` | 이 모듈의 규칙 정본 |
| `docs/decisions/*.md` | **결정 이력.** 팀원에게 "왜 이렇게 됐나"를 설명하는 것이 이것이다 |
| `docs/README.md` | 문서 안내 |
| `세션-시작-프롬프트.md` | 작업을 이어받는 사람의 진입점 |

| 미러하지 않음 | 왜 |
|---|---|
| `docs/md/` | 옛 명세서를 버전별로 얼려 둔 사본. 이력이라 지금 규약과 어긋나고 양이 크다 |
| `docs/openapi.json` | 생성물(`invoke openapi`). 원본에서 언제든 다시 나온다 |
| `docs/작업-프롬프트-기록.txt` · `docs/승격/` | 개인 작업 메모 |
| 코드 전부 | 볼트는 문서 보관소다. 코드는 GitHub·GitLab 두 원격에 이미 이중으로 있다 |

### 4. 파일명과 폴더 구조는 **원본 그대로** 둔다

볼트의 `Note Title Rules` 는 Projects 를 `프로젝트명-구분__주제` 반규칙형으로 권한다.
그런데 그 규칙대로 개명하면 **문서 안의 상대 링크가 전부 깨진다** — ADR 들이 서로를
`0007-research-boundary.md` 처럼 파일명으로 참조하고 있고, 그 참조가 결정 이력의 뼈대다.

그래서 파일명은 그대로 두고, **frontmatter `title` 에 한국어 제목을 넣어** Obsidian 이
그것을 표시하게 한다. 볼트 규칙의 목적("짧고 검색 가능")은 그쪽으로 충족되고,
링크는 살아 있다.

### 5. frontmatter 는 볼트의 `Metadata Rules` 를 따른다

```yaml
---
title: <문서의 첫 h1>
area: Projects
project: data-service
status: active
tags: [data-service, adr]
source: docs/decisions/0012-collection-scope-and-ia.md   # 정본 경로
synced: 2026-08-23 15:04 KST
commit: 9f1656d
---
```

`area`·`status` 는 볼트 공통 필드이고, `project` 는 Projects 전용 필드다(둘 다 규칙 문서에 있다).
`source`·`synced`·`commit` 셋은 **미러본에만 있는 것**이라, 그것이 곧 "이 파일은 자동 생성"이라는 표시다.

### 6. 인덱스 노트를 하나 만든다

`30_Projects/data-service/data-service.md` — 미러된 문서 목록 · 마지막 동기화 시각 · 정본 원격 주소.
볼트의 `Projects.md` 에서 여기로 들어오면 전체가 보인다. **이 파일도 자동 생성이다.**

## 근거

**볼트 규약이 이미 있으므로 그것을 따른다.** `Vault Structure` 가 `30_Projects` 를
"팀플, 캡스톤, 결과물, 포트폴리오"로 정의하고, `Home.md` 가 "원본은 건드리지 않고
정리된 미러만 둔다"를 운영 원칙으로 적어 두었다. 이 ADR 은 그 원칙의 적용례일 뿐이다.

**한 방향인 근거는 정본이 하나여야 한다는 것이다.** 구글 드라이브는 파일 단위로 동기화하고
git 은 커밋 단위로 이력을 남긴다. 두 체계가 같은 파일을 양쪽에서 고치면 병합 규칙이 없어
**드라이브의 마지막 저장이 이깁니다** — 그러면 git 이력이 조용히 거짓이 된다.

**`post-commit` 인 근거는 부작용의 자리다.** `invoke check` 는 CI 와 다른 머신에서도 도는
**검증** 명령이고, 검증이 레포 밖 파일시스템을 바꾸면 그 명령을 신뢰할 수 없게 된다.
반면 훅은 이 작업 사본에만 설치되는 로컬 장치라 부작용의 자리로 적절하다.

## 결과

**쉬워지는 것**

- 팀원 모집 시점에 볼트 링크 하나로 결정 이력 전체를 보여줄 수 있다.
- 커밋할 때마다 자동이므로 **두 사본이 갈라질 창이 없다.**
- 볼트에서 검색·백링크·그래프뷰가 ADR 사이의 참조 관계에 그대로 걸린다.

**어려워지는 것**

- **볼트 쪽에서 문서를 고칠 수 없다.** 고쳐도 다음 커밋에 덮인다. 메모를 남기고 싶으면
  미러 폴더 **밖**(예: `00_Inbox`)에 별도 노트를 만들고 링크해야 한다.
- 훅은 clone 마다 설치해야 한다. `invoke preflight` 가 알려 주지만, **그 안내를 무시하면
  조용히 안 돈다.** 볼트가 최신인지 의심스러우면 `python3 scripts/sync_obsidian.py --check` 로 잰다.
- 구글 드라이브 동기화가 밀리면 볼트 파일이 잠깐 낡을 수 있다. 이것은 이 레포가 통제하는
  범위 밖이고, `synced`·`commit` 필드로 **어느 시점 것인지는 항상 알 수 있게** 해 둔다.
