# 실습 아카이브 (수업 자료)

> 얼린 시점: 2026-08-01 (KST) · M1 리팩토링 직전 상태
> 접속: 서버를 띄운 뒤 <http://127.0.0.1:8000/practice/> (배포본은 `/practice/`)

M1(UI 셸) 리팩토링으로 앱의 화면 구조를 사이드바 셸 + 대시보드로 **전면 교체**했다.
교체 전 화면 8개는 수업에서 직접 만든 결과물이라 지우지 않고 이 폴더에 **원본 그대로** 남겼다.

## 1. 왜 `lecture/` 가 아니라 이 폴더인가

`lecture/` 는 **강사님 원본 저장소**(`edumgt/api-test2`)를 가리키는 git 서브모듈이다.
읽기 전용이며 매일 아침 `git pull` 로 최신화한다.

> 여기에 내 파일을 넣으면 **다음 pull 때 충돌이 난다.**

그래서 내 실습 결과물은 저장소 루트의 별도 폴더(`실습/`)에 둔다.
서브모듈과 경로가 겹치지 않으므로 강사님 자료를 아무리 pull 해도 충돌하지 않는다.

| 구분 | 위치 | 소유 | 수정 |
|---|---|---|---|
| 강사님 원본 | `lecture/` (서브모듈 → `edumgt/api-test2`) | 강사님 | **금지** — pull 만 한다 |
| 내 실습 아카이브 | `실습/` (이 폴더, 일반 폴더) | 나 | 얼려 둔다 (참고용) |
| 현재 작업본 | `app/` · `static/` | 나 | 계속 개발 |

## 2. 들어 있는 것

| 파일 | 화면 | 현재 앱에서의 위치 |
|---|---|---|
| `pages/index.html` | 랜딩 (화면 안내 · 데이터 흐름도) | `/guide` 로 이어짐 |
| `pages/stock.html` | 종목 통합 조회 | `/stock` (새 셸로 이식) |
| `pages/yf.html` | 야후 파이낸스 시세 | `/yf` (새 셸로 이식) |
| `pages/krx.html` | KRX 일별 시세 | `/krx` (새 셸로 이식) |
| `pages/kosis.html` | KOSIS 통계 실험실 | `/kosis` (새 셸로 이식) |
| `pages/quant.html` | 퀀트 분석 | `/quant` (새 셸로 이식) |
| `pages/users.html` | 사용자 CRUD API 테스트 | **현재 앱에서 내림** — 여기서만 본다 |
| `pages/tetris.html` | Canvas 테트리스 | **현재 앱에서 내림** — 여기서만 본다 |
| `assets/app.css` · `assets/app.js` | 당시의 공통 스타일·유틸 | `static/assets/` 는 계속 바뀐다 |

`/users` · `/tetris` 로 들어오면 이 아카이브의 해당 화면으로 자동 이동(redirect)한다.
예전 북마크나 수업 노트의 링크가 404 가 되지 않게 하기 위한 것이다.

## 3. 아카이브를 자기완결로 만든 부분

원본을 그대로 두되, **파일만으로 열려도 돌아가도록** 링크 두 종류만 바꿨다.

1. `/static/assets/app.css` · `app.js` → `../assets/app.css` · `../assets/app.js`
   (현재 앱의 `static/assets/` 가 M1 에서 크게 바뀌므로, 아카이브는 자기 사본을 본다)
2. 화면 간 이동 링크 `/krx` 등 → `krx.html` 등 상대경로
   (`assets/app.js` 의 `PAGES` 배열도 같이 바꿨다)

그 밖의 HTML·CSS·JS 는 손대지 않았다. **API 호출은 여전히 현재 서버의 `/api/...` 를 그대로 쓴다** —
백엔드 계층(`app/`)은 M1 에서 바뀌지 않았으므로 아카이브 화면도 그대로 동작한다.

## 4. 이 폴더를 고칠 일이 있다면

원칙적으로 **고치지 않는다.** 얼린 상태가 곧 수업 기록이다.
API 스펙이 바뀌어 아카이브 화면이 깨지면, 고치는 대신 이 문서에 "언제부터 무엇이 안 되는지"를 적는다.
